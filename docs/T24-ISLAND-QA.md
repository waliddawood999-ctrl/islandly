# T24 island requirements QA

Base: T21 `cc8c10a`. Target: draft PR into T21. No changes to the worker, timer, frame clock, Direct2D drawing or reserved-bar frame pacing. No renderer, settings UI, font or CSS edits.

`test/island-requirements.ps1 -Mode overlay` (also `reserved-bar`) runs the production host with a genuine foreground Win32 fixture. It changes the real Windows AppsUseLightTheme registry value for light/dark cases, restores it in finally, and runs Arabic/English. It verifies the whole owner HWND is hidden in fullscreen, checks hidden pixels against a pre-host textured reference, rejects reveal at the old pill location, requires top-edge hover to reveal without stealing foreground, then requires hiding on departure. The same fixture HWND changes to a normal window: Always and Approach must react, including leave/re-entry. It captures and checks exterior desktop pixels throughout both animations. Screenshot PNGs and status/log reports are uploaded even on failure. Fixture EXEs are CI-only and excluded by the existing explicit packaging inventory.

`test/island-shape-qa.ps1` independently rasterizes the specified rounded card/droplet mask and checks every nontransparent GPU readback pixel in every one of45open+45close frames at60Hz, for both languages/themes/materials (720PNG frames). Outside the one physical pixel raster-edge support, alpha must be exactly0; a deliberately injected white exterior pixel must fail the audit. Light/dark fill and portrait dimensions are asserted. This supplements the real desktop check, which catches window/DWM rectangles that a surface-only test cannot see. It does not claim to sample every physical display refresh between desktop captures.

The full existing `test/t20-visual.cjs` audit is rerun without fast mode or reduced assertions: all12 panels, Arabic RTL/English LTR, light/dark, acrylic/glass, overlay/AppBar,100/125/150% DPI. It requires height>width and a clearly portrait ratio, content-driven height without a large bottom gap, separated text/icons/tiles/footer,>=8px gear gap,>=12px tile labels and inline-start clock placement. Native context frames are freshly rendered first. The renderer uses deterministic IPC fixtures; actual foreground/material/composition behavior is tested separately with the native host.

Fullscreen fixes reuse the production raw-observation policy verified in T23, without importing its motion pipeline. No stale500ms verdict keyed only by HWND; foreground/location/display events invalidate raw observations. Monitor/setting policy applies live. QUNS_BUSY and ordinary maximized/captioned windows do not count as fullscreen. Owned, cloaked, hidden and minimized windows are excluded. A genuine borderless fullscreen client rectangle handles DWM frame metadata lag without a geometric tolerance. Entering actual fullscreen bypasses nonfullscreen burst deferral. Foreground changes reset a prior hover reveal.

Existing T13 full-owned-process RAM guards remain<180MB; the existing packaged workflow also verifies the exact accepted Electron SHA256, inventory and reproducible native builds. Native host changes require a new laptop SAC retest. No extra product EXE/DLL or idle resident process is introduced. Windows CI is distinct from a manual laptop/SAC test; the latter is not run here.
