## Scope and contracts

Live prayer state uses one next-event timeout, not a polling interval. The brief's **two-minute** adhan duration supersedes the older handoff's three minutes. Pre/iqama minutes, Ramadan Isha +30 for UmmAlQura only, imsak/iftar, explicit SMTC pause/resume, offline Hijri occasions and on-demand Quran catalogue/URL IPC are implemented. See HANDOFF for schemas and consumers.

Calendar timezone is fixed Asia/Riyadh. A **7,231-byte exact Intl-generated cache** covers AH 1400–1500 (roughly 1979–2077); tests compare every month start/middle/end with runtime Intl. scripts/generate-hijri-cache.js regenerates it offline. Outside that range the service falls back to runtime Intl, including its cold-allocation overhead. This is a cache of the requested Umm al-Qura API, not a different calendar algorithm.

Quran opens no network on import/startup or quran:url. An explicit quran:reciters request loads Arabic/English metadata, coalesces concurrent requests and caches for seven days. Expired validated cache is usable offline; no cache gives offline. Only HTTPS mp3quran subdomain servers and available surah IDs are accepted. No audio download/playback in main; Claude T12 owns audio/CSP/UI.

An earlier cache-enabled run (3fac73b, CI 40817573768) measured **+0.10 MB**, also below 3 MB. The latest -0.31 MB signed difference is ordinary working-set variation, **not a claim that adding the services saves RAM**. Both runs stay within budget. The checkpoint figure is sampled evidence, not a bound on every instantaneous allocation.

The original cold-runtime-Intl implementation measured +3.52 MB; bounded computation caches alone reduced that to +3.25 MB but still failed. An Intl-only control measured +2.39 MB. The exact precomputed calendar cache removed that avoidable startup residency. No GC, working-set trimming, private-byte substitution or heap-only budget was used.

Method: existing adhan/cities dependencies and legacy calculations warmed first; 15s warmup and 30 one-second Electron Browser working-set samples before and after cold loading T10 modules/start/get calls. Quran stayed unopened: **0 requests**; 1 initial prayer-state event. This measures incremental backend Browser working sets, not total application RAM, and is not a native T9 benchmark.

## Reproduce

On Windows from this branch:

```powershell
npm ci
npm test
npx electron test/islamic-ipc.js
npx electron test/islamic-memory.js
```

The latter writes islamic-memory-full.json and fails if the added mean working sets reach 3 MB or idle Quran requests are nonzero. Optional diagnostic: set ISLANDLY_ISLAMIC_PROBE=intl-only before running it; that experiment does not waive the full-service budget.
