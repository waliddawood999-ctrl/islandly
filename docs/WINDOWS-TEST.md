# قائمة اختبار ويندوز (ينفذها وليد على جهازه)

هذي الأشياء ما نقدر نختبرها في بيئة Linux أو في CI بدون شاشة. نفّذ كل بند، وحط ✅ أو ❌ واكتب ملاحظة قصيرة. لو ❌ صوّر الشاشة وأرسل ملف السجل: كليك يمين على أيقونة الجزيرة ← "فتح مجلد السجلات والبيانات" ← `islandly.log`.

اكتب فوق: رقم الإصدار (من الإعدادات)، نسخة ويندوز (10 أو 11)، ونوع الجهاز.

## T7 — Native surface acceptance (pending; no manual Windows results claimed)

Record Windows build, monitor topology and scaling before each run.

| Check | Steps and expected evidence | Result |
|---|---|---|
| Colour opt-in | Default surfaceTint=false: no GetPixel samples. Opt in through backend setting until Claude exposes the control. In overlay mode, compact/resting island receives surface:tint RGB. Expanded, hidden, fullscreen and disabled sampling produce no samples. Rapid visibility changes never exceed one sample batch per 500ms. | Pending |
| Reserved strip | Set islandMode=appbar. Maximize a browser: it starts below the reserved top strip. Expanding the island does not increase the reservation. Return to overlay and confirm the strip disappears. | Pending |
| Taskbar coexistence | Repeat with the taskbar at the top, auto-hide on/off, and another AppBar. Confirm QUERYPOS preserves their reservations and no ABN_POSCHANGED loop appears. | Pending |
| Mixed DPI/monitors | Select monitorId for a secondary display at a negative origin, 100% then 150%/200%. Check the strip appears on the selected display only. Change DPI, unplug/reconnect and change primary display; check reposition/fallback and no leftover strip. | Pending |
| Explorer restart | While in AppBar mode restart Windows Explorer in Task Manager. Confirm TaskbarCreated re-registers exactly once and the strip returns. | Pending |
| Clean shutdown | Quit normally and inspect userData: appbar-marker.json is removed after ABM_REMOVE. Repeat with island window close and renderer failure. | Pending |
| Forced termination/relaunch | Register AppBar, confirm marker contains PID/edge/physical rect, End task on Islandly, then relaunch (also try overlay mode). Dead PID recovery uses the new HWND for NEW/SETPOS/REMOVE and clears marker. Check no empty top space remains. Do not treat a unit/mock pass as this manual result. | Pending |
| Live marker | Launch a second process against the same userData while the first is alive. It must not remove the first process's bar or replace its marker. | Pending |
| Failure fallback | Simulate unavailable native calls or failed SETPOS. Island stays usable as overlay; no new reservation remains. A failed REMOVE retains the marker for retry/recovery. | Pending |

Linux tests exercise lifecycle with fake Win32 calls, including a real child-process kill/relaunch. Windows CI separately exercises the real native ABI and NEW/QUERYPOS/SETPOS/REMOVE. Neither establishes visual acceptance on a user desktop.
